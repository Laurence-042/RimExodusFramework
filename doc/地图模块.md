# REF 地图模块契约

跨图格查询的 API、坐标方法论和第三方算法接入流程见 [跨图空间查询](跨图空间查询.md)。该服务不依赖渲染或战斗开关，也不自动遍历、生成或唤醒地图。

公共程序集由 RimExodus Framework 1.0.1 独立 Mod 提供，在 Mod 初始化时安装公共补丁，战斗补丁另由消费方按需安装。Delta-V 唯一使用 REF，RimExodus 提供启动时选择的 REF/legacy 后端。原始目标见 [迁移备忘录](迁移备忘录.md)，安装、构建与验证入口见 [README](../README.md)。

公共补丁自动安装只处理显式标记 `[HarmonyPatch]` 且未标记 `[CombatPatch]` 的类型；MapPreview 等手动注册的软兼容辅助类不进入自动扫描，避免仅因存在 Prefix/Finalizer 同名方法就被当作缺少目标的补丁。补丁安装失败会撤销自身补丁并缓存失败，进程内不重复尝试；消费方不能继续使用不可用服务。生成图渲染门禁保留其他 Mod 的原始读取或过滤结果，再追加自身过滤，兼容两种补丁顺序。

## 当前能力与接线

软兼容注册另行处理：MapPreview 缺失时不挂钩，成功后重复 Register 不双挂，成员不匹配时一次告警；延迟 CE 炮塔/CIWS 注册各自保护实际回调内的反射和绑定，避免错误逃出长事件。逐钩子成功允许部分能力保留，汇总“注册完成”不等于全部功能通过。RE/REF 详细审计与两后端测试边界见同级消费方 `RimExodus/doc/兼容层注册审计.md`。

区域模板、区域归档和 prefab 使用一个内容模型；整图只是全范围选择附带原版地图状态。当前**没有自动清空任意已有区域并事务式替换的 API**。区域 Rebuild 会落地内容，调用者应使用可丢弃的新地图，并检查结果；失败不能当成成功封存并删除原记录。RimExodus 已在 1100 清障与自然恢复后调用公共重建；为可回退验证阶段保留旧记录，公共文档通过 XML 内嵌保存。

## 使用约束

- 游戏初始化时调用 `MapModule.Install()`，所有可变服务状态使用当前游戏的 `MapRuntime`。按消费者提供唯一 owner；同一地图不能被两个 owner 同时登记。地图移除释放注册，重新登记获得新的代次。
- `MapRenderPlan.Collect` 是选择性捕获路径，不切换 `Find.CurrentMap`，不调用 `MapUpdate`。矩阵从源图局部坐标映射到当前显示参考系；聚焦图由消费者传 identity。捕获命令只能在当前帧同步消费，不能跨帧缓存属性范围。`CustomDraw` 输出源图局部命令，由 plan 应用矩阵和过滤器。原版回调路径另见下面的契约。
- 1.7 `UnityStubs.Matrix4x4.ToNumerics` 保留列向量矩阵布局，不转置；捕获与再次变换均左乘显示变换，公开 `MapDrawCommand.Matrix` 按原布局还原。此前误按行向量约定组合，使非聚焦船壳的 Comp 实时上层偏离；普通炮塔的独立命令不经过这次非 identity 捕获，因此不受该错误影响。
- 图层过滤覆盖当前游戏程序集中的 `MapDrawLayer.DrawLayer` 实现；第三方重写层的精细过滤尚未接入，可使用命令过滤。不要假定线程局部捕获上下文能传入第三方绘制任务。
- `MapDrawBackend` 使用 `Attach → BeginFrame → BeginGroup → Draw → Finish`，每帧显式建立组。当前分层用于背景图/前台效果，不允许消费者各自创建彼此冲突的分组编排。
- `Capture` 冻结选择掩码；默认导出 Building/Item，按锚格选择多格 Thing。`include`/`order` 可由调用方提供。Foundation 认领、主台/武器重置、导弹仓与标记展开均在 Delta-V 适配器中，公共层没有飞船知识。
- `Clone=true` 用于模板复制；`Clone=false` 用于内容身份恢复，原对象必须已经离开游戏的有效对象集合。区域模式不是完整地图快照：地图组件、全局任务关系等需要全图状态或后续明确的区域侧车契约，不能承诺任意 Mod 状态都可封存。
- 全图恢复要求相同 Map ID 和 parent，且不能有现存图占用身份。捕获核对原版持久 Thing 清单，恢复核对 Pawn needs 和已生成清单；失败保留调用方的归档数据。卸载拒绝当前聚焦图、战斗占用、存活子口袋图及已识别的外部事件引用。
- 捕获在写入前用原版 `CompressibilityDecider.DetermineReferences` 与 `IsSaveCompressible` 生成必须完整保存的 Thing ID 清单，临时 compressor 在成功／异常时均还原。原版 `Map.ExposeData` 返回前会清空 compressor，因此保存后只核对 XML ID，不再调用压缩判定。不能仅按 Def 的 `saveCompressible` 放行，否则会漏检被任务／预留等引用而必须完整保存的对象。2026-11-01 新增 12 项实际 1.7 压缩规则回归，覆盖原报错复现、引用清单、原版写入分类一致、缺失拒绝及上下文清理；完整地图往返仍待游戏内验收。
- 整图 XML 的外部引用由 `MapArchive.ExternalReferences` 统一枚举：派系、意识形态及戒律、任务、四类 Pawn 政策（饮食／服装／药物／阅读）、Tale、世界对象／口袋图 parent、世界 Pawn、全局 BattleLog 的 Battle／LogEntry、PlayLog 条目及其他地图的递归 Thing。世界对象持有的内容和世界 Pawn 的随身内容也递归登记；MapParent 的内容由地图循环统一处理并排除源图。恢复注册同一清单后才解析交叉引用，不复制这些全局对象。开发模式保存检查也承认这些外部对象由游戏其余部分持有，避免片段存档的假阳性；未知引用、不同对象的重复 ID 和内外身份冲突仍报告。此清单不延长原版日志条目的寿命，不保证已被原版清除的历史记录仍能恢复。
- Scribe 操作必须在主线程安全边界同步执行；嵌套或正在存读档时不进入新操作。公共层不新建跨帧静态游戏状态。
- 降频减少执行机会，不补算通用模拟时间；可选移动补偿只调整 Pawn 路径费用。原版按绝对 tick 计算的逻辑仍看到全局时间，不等同于独立时间轴。旧 `CombatLease` 仍需 `Dispose`，但不再强制全图全速，域关闭后 `Valid=false`；逐图自动战斗桥接不使用该旧 API。
- LOS 的逐图线段由调用方的权威几何提供，公共层调用原版逐段检查；掩体在目标图坐标计算。显示矩阵不能用作 Delta-V 命中真相。

### Prefab 禁止建屋顶区域（2026-11-06）

`MapPrefabDocument.noRoof` 保存选择掩码内原版 `Area_NoRoof` 的局部格，XML 为 `<noRoof><li>(x, 0, z)</li></noRoof>`。捕获、XML 读写与旋转导入均走现有 prefab 管线；重建在实体 SpawnSetup 之前设置目标 `NoRoof=true`、`BuildRoof=false`，避免原版自动补顶封住露天设备安装位。重复格、文档／掩码外格在读写时拒绝，目标越界在修改地图前拒绝，受保护格不改。已有实体屋顶仍按独立屋顶层保存，区域标记不瞬间删除物理屋顶，后续移除由原版工作系统处理。运行期存档由原版 AreaManager 完成，不新增缓存或教程处理。四向放置、原版区域格写入、保护与捕获往返的离线回归通过；游戏内自动补顶及存读档待验收。

### Prefab 环境层（2026-11-05）

`MapPrefabDocument.environment` 与地形、基架、屋顶共用 `MapPrefabs.Capture/Rebuild`。每条 `PrefabEnvironmentEntry` 保存 `temperature`、`vacuum` 与同值采样的局部 `cells`；不保存 Room ID、房间边界或第二套房间拓扑。捕获只纳入选择掩码内、`UsesOutdoorTemperature=false` 的房间格，使用原版 `Room.Temperature/Vacuum` 读值。整图 `mapState` 继续走原版保存，不重复写环境层。

XML 为 `<environment><li><temperature>21</temperature><vacuum>0</vacuum><cells><li>(x, 0, z)</li></cells></li></environment>`。无环境数据可为空；温度范围 −273.15～1000°C，真空度 −0.1～1（沿原版 setter 范围，0 为无真空，1 为完全真空）。缺失值、非有限值、重复格、越界格及掩码外格均拒绝；放置前另检查旋转后的目标边界。

屋顶落位成功后，先经原版增量房间更新，再按与地形相同的 `PrefabUtility` 局部格变换恢复环境，最后调用 `Completed`。整个 prefab 放置期间临时启用房间更新，使氧气泵等原版设施在 SpawnSetup 查询房间时也有效；结束或异常均恢复原开关，消费方无需先启用房间系统。目标室外格和无 Room 格不写入；多个采样映射到同一目标房间时按格数加权，未采样的目标房间格保留其当前值参与加权。因此完整房间原样恢复，局部导入不会把同房间其余空气全部替换。破口房间真空度遵守原版 `ExposedToSpace`；门洞真空度仍由原版邻室计算。若目标房间包含任何 `ProtectCell` 格，整个房间环境不改，避免共享 Room 状态绕过保护。

生成期通过 `MapPrefabs.Rebuild` 成功导入环境的地图由当前 `MapRuntime.PrefabEnvironment` 暂记。原版 `Map.FinalizeInit → RebuildAllRegionsAndRooms` 会清空温度缓存并销毁 Room；公共 Prefix 先通过既有 `MapPrefabEnvironment.Capture` 采样当前真实室内值，Postfix 经既有 `Apply` 恢复到新 Room，随后原版继续电网／设施初始化。保存当前值而非重放原模板，因而保留多次导入、保护房间和后续生成步骤的修改；重复全量重建也读取当时值。无 prefab 环境导入的地图与普通已生成地图导入不登记、不干预。`FinalizeInit` 成功或异常均释放登记，地图删除走 `MapRuntime.Forget`，换游戏随实例释放；临时采样只存在于同调用栈，不序列化、不轮询。整图读档继续使用原版环境保存层，不登记此生成流程。

2026-11-06 增加生成期自动登记、房间身份替换、实际环境值／重复重建、露天与删除释放回归；环境专项共 64 项，安装回归实际绑定新增两处原版方法。两版 REF／Delta-V 编译通过，完整新档生成与人物活动仍待用户实测。消费方无需也不得追加教程专用环境恢复。

游戏内仍需用新档覆盖：带成瘾与亲属关系船员、风格／艺术品、储物容器的整图远离归档与追近恢复；归档期间存读档；连续多图生成／归档；恢复后的房间温度、真空、电网、任务和 parent 状态。第三方私有注册表、跨图对象的反向持有，以及原版／第三方在嵌套 ExposeData 内吞掉异常后的全部状态保真度，未由上述离线 fixture 证明。

### RE 接入新增 API 契约

- 绘制：旧 `BeginFrame()` 保持不清颜色，`BeginFrame(true, color)` 在 1.6 追加颜色/深度清理；1.7 由原生帧管理目标清理。`MapDrawBackend(foreground, name, preserveRenderLayer:true)` 保留辅助 pass 的原生 layer，不将 WaterDepth 编码为主地图深度组。普通地表命令仍用默认分组，捕获命令连同属性范围只在当前帧消费。
- 调度：原五参数 `Set` 保留；六参数重载的 `compensateMovement` 默认不隐式打开。RE 指定 true，移动补偿为 `100/p`，全速例外和 0% 返回 1。0% 的 fullSpeed 谓词变化后须在安全边界调用 `RefreshRegistration`；替换谓词或比例会自动更新注册。位置 setter/直接定位只置脏，`GameComponentTick` 处理变化对象；无 tick 的普通 Thing 不进入暂停登记集合。`Release(map, owner, restoreTicks:false)` 用于立即整图休眠的交接。
- 区域：七参数 `Capture` 的 `includeIntersectingFootprints` 允许多格实体与掩码相交即入选；旧签名保留锚格语义。`MapPrefabDocument.ToXml/FromXml` 支持嵌入消费方存档；实体解析在独立安全的 Scribe 窗口执行。`PrefabPlacement.ProtectCell` 同时保护 terrain/foundation/roof 与建筑 footprint；默认 `SkipProtectedThings=true` 返回跳过列表，false 在写入前报告 footprint 冲突。`PreserveFactions=true` 保留实体派系并解析外部引用，克隆仍分配新实体/Verb 身份。读取与放置失败通过 `Errors` 报告，不得据此丢弃原记录。
- 自动战斗：启动安全点调用 `MapCombatModule.Install()`；`Combat.Enable(map, policy)` 也确保安装完成。`MapCombatPolicy.Owner` 归属消费方，Offset 表示 `targetLocal + offset = sourceLocal`；Available、CellOwner、Neighbors、HasNeighbors 和可选 CanApproach/SuppressTargetSearch/IgnoreProjectile 由消费方提供。两端须登记同一 policy 且有效。框架不推断世界地块或使用显示矩阵作为命中坐标。
- 关闭战斗：`Combat.Disable(map)` 移除逐图登记并使相关目标/弹丸记录失效；`policy.Enabled=false` 对该策略所有地图做同样清理。临时不可用前由消费方调用 `Invalidate(map)`，几何变换改变后也应失效旧目标。关闭图不调用邻居枚举、格归属和弹丸迁移，不获得 tick 提速；没有战斗周期任务。地图删除调用 Forget。弱引用目标/弹丸表属于当前 MapRuntime，换档不继承。
- 战斗安装独立于公共模块。只有 Delta-V 时不安装 REF 战斗补丁；与启用 REF 战斗的 RE 同装时，关闭图仍承担公共 Harmony 方法分派和常数级逐图判断，不能将其描述为绝对零 CPU 指令。CE 保持软反射，缺失不绑定，签名漂移 Warning；原版与 CE 弹丸在当前真实图完成关闭后的剩余原生生命周期。
- 原版 `TryCastShot` 的跨图门在原地图读取之后执行；第三方若把目标 `Thing.Map` 换成自身的宿主图读取（如 VMF `BaseMap(Thing)`），该结果先进入门，只有消费方登记的有效战斗连接才覆盖它。补丁先后顺序均须保留该链。
- 生成：消费方先补齐引用数据，再 `Acquire(owner, completeSynchronously)`，创建图后 `Bind(owner, map)`；完成函数须在同一次调用中结束当前任务并释放，不可等待下一帧或递归 GenerateMap。只有清理完 MapGenerator 静态状态才 `Release(owner)`；清理失败不得释放后继续下一任务。原生 GenerateMap 先 `Drain()` 当前增量任务再登记同步占用；Finalizer 释放。MapPreview 在 GeneratePreview 入口、暂停之前登记，后台线程等待当前占用结束；同线程嵌套立即拒绝。

以上新增能力完成代码接线，双版本实机结果仍按下面的验证边界区分，不复用迁出前的测试结论。

构建和测试入口见 [README](../README.md)。独立 Mod 的 1.6/1.7 加载、地图分层与切图、非矩形区域导出/重建/存读档、整图归档往返、生成中保存和失败释放均需按新档验证。用户已确认迁出前 1.7 护盾与导弹架上层修正有效；这不替代独立打包后的实机验收。

尚待迁入而非“只待验收”的工作：任意既有区域的清空/替换事务、公共资源池与 Gravship 搬运。原版绘制的特殊 GPU 状态边界见下节；当前 DLL 不代表迁移备忘录所有能力已经完成。

## 原版回调绘制契约

消费方通过 `MapRuntime.Current.Rendering.SetProvider(owner, callback)` 登记，每帧在原版地图更新前提供 `MapRenderPlan` 列表。列表可以包含 identity 聚焦图，以便它的矩形覆盖层也接受凸边界裁切。`SetProvider(owner, null)` 注销；`Clear()` 释放本服务所有绘制资源但保留 provider，适用于路径切换。图删除释放该图缓存，Current.Game 变更前清空资源，不序列化。该入口只使用 plan 的 Source、Transform、LocalView 和 `OverlayFootprint`；Collect 的层过滤、CustomDraw 等选择性选项不参与。

框架包裹游戏原本每帧一次的 `Map.MapUpdate`，不额外调用它、不增加 tick 或组件 Update 次数。在邻图窗口内，同线程 `Find.CurrentMap` 查询返回源图，`CameraDriver.CurrentViewRect` 返回逆投影视区；不调用真实焦点 setter，也不重放相机输入/更新。邻图追加一次 `MapComponentUtility.MapComponentOnDraw`；聚焦图仍由原版 MapInterface 调用。Finalizer 在异常时恢复上下文。窗口之前已执行的其他 Mod Prefix、跨线程绘制、缓存的真实焦点均不被强制改写。

局部视区 Postfix 使用 `Priority.Last`，在通常优先级的相机 Mod 计算完成后返回 plan 的 `LocalView`；作用域外完全保留相机结果。它不承诺覆盖第三方另设更晚顺序的补丁。`MapRenderPlan.CurrentNativeView` 返回当前线程的原版回调计划，无窗口时为 null。适配层只能同步读取，不跨帧保留；Source 表示算法输入的局部坐标系，Transform 表示局部到显示坐标的映射，不能据此修改模拟归属。

可见性判定必须先统一坐标系，再运行剔除。若第三方视锥位于显示坐标，使用 `Transform.BoundsToDisplay(min,max,out displayMin,out displayMax)` 得到保守轴对齐包围盒，模型矩阵使用 `Transform.Matrix * modelMatrix`。该包围盒支持仿射旋转/缩放，只用于可见性，不用于格归属或碰撞。最终提交仍从原始局部输入投影一次；不要把剔除用的变换写回网格、缓存或真实相机。

1.7 的 `IsoRimCullingCompat` 独立软检测 `Peren.IsoRim17`，在启动长事件收尾绑定 `Cull.BoxVisible(Vector3,Vector3)` 与 `Cull.MeshVisible(Mesh,Matrix4x4)`，仅在非 identity 的原版回调窗口转换判定参数。这两个入口各自直接测试平面，不相互调用。缺失 Mod 时不绑定；类型/签名漂移 Warning，绑定失败撤销本适配钩子，不中断 REF 安装；成功输出可核对的绑定日志。适配不读取消费方或地图类别，不改 IsoRim 全局视锥。其矩形土层边缘、首次显示的私有 stale 重建及其他私有 GPU 状态仍不在本适配范围。

1.7 在 `MeshDrawSubmission.Enqueue(in MeshDrawCommand)` 处理最终网格命令，保留原版队列、pass、layer、instancing/storage，不使用自绘制路径的背景分组排序。保存并恢复引擎 float/vector/matrix/texture 全局表和 LightOverlay 颜色；按 shader 布局冻结常规参数、材质和属性块，原属性块优先，shader 显式默认值不被同名全局值覆盖。1.6 在普通 DrawMesh 和直接实例矩阵提交入口变换坐标，使用材质池冻结绘制参数，记录并恢复窗口内五类 SetGlobal 调用；保留原属性块，并按帧清色。当前不隔离 shader 全局数组/关键字、独立 uniform block、GPU 间接实例缓冲和任意 Mod 私有 static。

`OverlayFootprint` 是消费方持有的不可变凸多边形，坐标为源图局部 X/Z。仅裁切跨度超过半张地图、厚度小于 0.01 的可读平面三角网格，按重心权重插值原有属性。包围盒只用于水平跨度初筛，不能用于否定平面性：Mod 可以合法地加厚剔除包围盒。最终跨度与厚度只由当前 submesh 的索引实际引用的顶点计算，不受未使用顶点或其他 submesh 干扰；小物体、三维模型、实例批次和无法安全插值的格式不改写。1.7 缓存按网格版本、submesh、局部矩阵失效，120 帧不用即释放；1.6 没有公开网格修改版本，按帧重填复用网格。它不是整场景三维遮罩，也不理解自定义 shader 的坐标编码。

该机制没有任何 Surveillance Shift 或 IsoRim 名称/类型检测。通过地图组件 Update + CurrentMap 门禁绘制的普通迷雾能进入这条路径，但不创造跨地图视野；逐图可见性数据仍由原 Mod 维护。依赖 CameraDriver.Update、私有视锥、第一人称墙体缓存、全屏后处理、绕过 Enqueue 的批量/持久提交等效果仍可能需要适配。不得将“高兼容性”描述为任意 Mod 的像素级等价。
