# REF 地图模块契约

公共程序集由 RimExodus Framework 1.0.0 独立 Mod 提供，在 Mod 初始化时安装自身补丁。Delta-V 唯一使用 REF，RimExodus 尚未接入。原始目标见 [迁移备忘录](迁移备忘录.md)，安装、构建与验证入口见 [README](../README.md)。

补丁安装失败会撤销自身补丁并缓存失败，进程内不重复尝试；消费方不能继续使用不可用服务。生成图渲染门禁保留其他 Mod 的原始读取或过滤结果，再追加自身过滤，兼容两种补丁顺序。

## 当前能力与接线

| 能力 | DLL 实现 | Delta-V 接入与边界 |
| --- | --- | --- |
| 自定义多地图绘制 | `MapDrawCapture`、`MapDrawCommand`、`MapDrawBackend`；1.7 保留原生材质属性、pass、instancing/storage 元数据，分组排序并清深度 | 已接入船壳捕获和提交；船壳选择、喷焰、炮塔和层序政策仍由 Delta-V 提供 |
| 默认原版绘制入口 | `MapRenderPlan` 调用 MapDrawer、DynamicDrawManager、地图效果；提供图层/命令过滤、自定义绘制、叠层和边缘裁剪开关 | DLL 已提供，尚未成为 Delta-V 的显示模式；未宣称达到全部原版视觉保真。逐图全局 shader、光照/水面、第三方层和实例化绘制需继续验证 |
| 坐标互映射 | `MapTransform` 点/方向双向映射、跨图转换、保守视区、负格坐标向下取整；plan 使用同一矩阵拾取 | 已用于船壳逆向视区；`SpaceTransform` 继续负责宇宙与球面坐标，不产生第二套物理状态 |
| 无 tile 口袋图 | `PocketMaps` 创建/注册；`PocketMapHostService` 查找/创建公共 sourceMap 宿主 | 宿主、普通船图创建和同步小图注册已接入；parent 的 Def、环境、派系和隐藏政策仍属于 Delta-V |
| 统一区域内容 | `IRegionSelection`、`CellSelection`、`AreaSelection`、`WholeMapSelection`；统一 `MapPrefabs.Capture/Rebuild` 与 `MapPrefabDocument` | 居住区导出与 prefab 重建已接入；不绑定 Home，任意掩码可用。整批解析逐实例引用；克隆重新分配 Thing/Verb 身份；保留身份时拒绝现存身份冲突 |
| 全图状态与卸载 | 全图选择的 `includeMapState` 在同一文档中保存原版 Map 状态层；`CaptureWholeMap/RestoreWholeMap` 是该入口的包装；`MapArchive` 处理原版存取、身份/清单验证和卸载 | 已接入现有远距离归档恢复。Map 组件、Pawn、网格由原版 ExposeData 保留；归档期间的 objectId、位姿和摘要仍由 Delta-V 管理 |
| tick 速率 | `MapTickRates`：0–100%，普通/rare/long 桶，0 速率注销与恢复注册，全速例外和战斗占用 | 已接入休眠/唤醒及宿主、空闲池图、生成中图的停止政策。中间速率由 API 提供，Delta-V 本轮不新增距离降频政策 |
| 可开关跨图战斗基础 | `MapCombatDomain.Enabled`、`MapTarget`、战斗租约、射程、分段原版 LOS、目标图掩体查询与原版伤害入口；占用期间防休眠/归档 | API 已提供，默认禁用。**未接入原版 Verb/Projectile 自动跨图射击补丁**，也未替换 Delta-V 的 SpaceProjectile/SpaceCollision/护盾链；不能把接口提供等同于原版跨图射击已完成迁入 |
| 生成互斥 | `MapGenerationCoordinator` 租约/同步 drain；1.7 按真实 IL 缩小后台生成的渲染门禁 | Delta-V 增量生成已接入占用、绑定、失败释放；GenStep 执行器、保存门禁、资源池和 Gravship 搬运仍留在 Delta-V |

区域模板、区域归档和 prefab 使用一个内容模型；整图只是全范围选择附带原版地图状态。当前**没有自动清空任意已有区域并事务式替换的 API**。区域 Rebuild 会落地内容，调用者应使用可丢弃的新地图，并检查结果；失败不能当成成功封存并删除原记录。RimExodus 的区域封存/按需重建接线仍是后续工作，不另建一套存储格式。

## 使用约束

- 游戏初始化时调用 `MapModule.Install()`，所有可变服务状态使用当前游戏的 `MapRuntime`。按消费者提供唯一 owner；同一地图不能被两个 owner 同时登记。地图移除释放注册，重新登记获得新的代次。
- `MapRenderPlan` 不切换 `Find.CurrentMap`，不调用 `MapUpdate` 推进模拟。矩阵从源图局部坐标映射到当前显示参考系；聚焦图由消费者传 identity。捕获命令只能在当前帧同步消费，不能跨帧缓存属性范围。`CustomDraw` 输出源图局部命令，由 plan 应用矩阵和过滤器。
- 1.7 `UnityStubs.Matrix4x4.ToNumerics` 保留列向量矩阵布局，不转置；捕获与再次变换均左乘显示变换，公开 `MapDrawCommand.Matrix` 按原布局还原。此前误按行向量约定组合，使非聚焦船壳的 Comp 实时上层偏离；普通炮塔的独立命令不经过这次非 identity 捕获，因此不受该错误影响。
- 图层过滤覆盖当前游戏程序集中的 `MapDrawLayer.DrawLayer` 实现；第三方重写层的精细过滤尚未接入，可使用命令过滤。不要假定线程局部捕获上下文能传入第三方绘制任务。
- `MapDrawBackend` 使用 `Attach → BeginFrame → BeginGroup → Draw → Finish`，每帧显式建立组。当前分层用于背景图/前台效果，不允许消费者各自创建彼此冲突的分组编排。
- `Capture` 冻结选择掩码；默认导出 Building/Item，按锚格选择多格 Thing。`include`/`order` 可由调用方提供。Foundation 认领、主台/武器重置、导弹仓与标记展开均在 Delta-V 适配器中，公共层没有飞船知识。
- `Clone=true` 用于模板复制；`Clone=false` 用于内容身份恢复，原对象必须已经离开游戏的有效对象集合。区域模式不是完整地图快照：地图组件、全局任务关系等需要全图状态或后续明确的区域侧车契约，不能承诺任意 Mod 状态都可封存。
- 全图恢复要求相同 Map ID 和 parent，且不能有现存图占用身份。捕获核对原版持久 Thing 清单，恢复核对 Pawn needs 和已生成清单；失败保留调用方的归档数据。卸载拒绝当前聚焦图、战斗占用、存活子口袋图及已识别的外部事件引用。
- Scribe 操作必须在主线程安全边界同步执行；嵌套或正在存读档时不进入新操作。公共层不新建跨帧静态游戏状态。
- 降频表示减少执行机会，不补算时间。原版按绝对 tick 计算的逻辑仍看到全局时间，不等同于独立时间轴。战斗租约恢复参与地图的全速 tick，必须 `Dispose`；关闭域阻止新交战，已有租约允许完成。
- LOS 的逐图线段由调用方的权威几何提供，公共层调用原版逐段检查；掩体在目标图坐标计算。显示矩阵不能用作 Delta-V 命中真相。

## 验证与待完成

构建和测试入口见 [README](../README.md)。独立 Mod 的 1.6/1.7 加载、地图分层与切图、非矩形区域导出/重建/存读档、整图归档往返、生成中保存和失败释放均需按新档验证。用户已确认迁出前 1.7 护盾与导弹架上层修正有效；这不替代独立打包后的实机验收。

尚待迁入而非“只待验收”的工作：完整原版跨图射击链、区域封存的清空/替换事务、公共资源池与 Gravship 搬运、完整默认多图绘制的逐图 shader 状态隔离。当前 DLL不代表迁移备忘录所有能力已经完成。
