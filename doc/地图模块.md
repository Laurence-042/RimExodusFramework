# REF 地图模块契约

公共程序集由 RimExodus Framework 1.0.0 独立 Mod 提供，在 Mod 初始化时安装公共补丁，战斗补丁另由消费方按需安装。Delta-V 唯一使用 REF，RimExodus 提供启动时选择的 REF/legacy 后端。原始目标见 [迁移备忘录](迁移备忘录.md)，安装、构建与验证入口见 [README](../README.md)。

公共补丁自动安装只处理显式标记 `[HarmonyPatch]` 且未标记 `[CombatPatch]` 的类型；MapPreview 等手动注册的软兼容辅助类不进入自动扫描，避免仅因存在 Prefix/Finalizer 同名方法就被当作缺少目标的补丁。补丁安装失败会撤销自身补丁并缓存失败，进程内不重复尝试；消费方不能继续使用不可用服务。生成图渲染门禁保留其他 Mod 的原始读取或过滤结果，再追加自身过滤，兼容两种补丁顺序。

## 当前能力与接线

软兼容注册另行处理：MapPreview 缺失时不挂钩，成功后重复 Register 不双挂，成员不匹配时一次告警；延迟 CE 炮塔/CIWS 注册各自保护实际回调内的反射和绑定，避免错误逃出长事件。逐钩子成功允许部分能力保留，汇总“注册完成”不等于全部功能通过。RE/REF 详细审计与两后端测试边界见同级消费方 `RimExodus/doc/兼容层注册审计.md`。

区域模板、区域归档和 prefab 使用一个内容模型；整图只是全范围选择附带原版地图状态。当前**没有自动清空任意已有区域并事务式替换的 API**。区域 Rebuild 会落地内容，调用者应使用可丢弃的新地图，并检查结果；失败不能当成成功封存并删除原记录。RimExodus 已在 1100 清障与自然恢复后调用公共重建；为可回退验证阶段保留旧记录，公共文档通过 XML 内嵌保存。

## 使用约束

- 游戏初始化时调用 `MapModule.Install()`，所有可变服务状态使用当前游戏的 `MapRuntime`。按消费者提供唯一 owner；同一地图不能被两个 owner 同时登记。地图移除释放注册，重新登记获得新的代次。
- `MapRenderPlan` 不切换 `Find.CurrentMap`，不调用 `MapUpdate` 推进模拟。矩阵从源图局部坐标映射到当前显示参考系；聚焦图由消费者传 identity。捕获命令只能在当前帧同步消费，不能跨帧缓存属性范围。`CustomDraw` 输出源图局部命令，由 plan 应用矩阵和过滤器。
- 1.7 `UnityStubs.Matrix4x4.ToNumerics` 保留列向量矩阵布局，不转置；捕获与再次变换均左乘显示变换，公开 `MapDrawCommand.Matrix` 按原布局还原。此前误按行向量约定组合，使非聚焦船壳的 Comp 实时上层偏离；普通炮塔的独立命令不经过这次非 identity 捕获，因此不受该错误影响。
- 图层过滤覆盖当前游戏程序集中的 `MapDrawLayer.DrawLayer` 实现；第三方重写层的精细过滤尚未接入，可使用命令过滤。不要假定线程局部捕获上下文能传入第三方绘制任务。
- `MapDrawBackend` 使用 `Attach → BeginFrame → BeginGroup → Draw → Finish`，每帧显式建立组。当前分层用于背景图/前台效果，不允许消费者各自创建彼此冲突的分组编排。
- `Capture` 冻结选择掩码；默认导出 Building/Item，按锚格选择多格 Thing。`include`/`order` 可由调用方提供。Foundation 认领、主台/武器重置、导弹仓与标记展开均在 Delta-V 适配器中，公共层没有飞船知识。
- `Clone=true` 用于模板复制；`Clone=false` 用于内容身份恢复，原对象必须已经离开游戏的有效对象集合。区域模式不是完整地图快照：地图组件、全局任务关系等需要全图状态或后续明确的区域侧车契约，不能承诺任意 Mod 状态都可封存。
- 全图恢复要求相同 Map ID 和 parent，且不能有现存图占用身份。捕获核对原版持久 Thing 清单，恢复核对 Pawn needs 和已生成清单；失败保留调用方的归档数据。卸载拒绝当前聚焦图、战斗占用、存活子口袋图及已识别的外部事件引用。
- Scribe 操作必须在主线程安全边界同步执行；嵌套或正在存读档时不进入新操作。公共层不新建跨帧静态游戏状态。
- 降频减少执行机会，不补算通用模拟时间；可选移动补偿只调整 Pawn 路径费用。原版按绝对 tick 计算的逻辑仍看到全局时间，不等同于独立时间轴。旧 `CombatLease` 仍需 `Dispose`，但不再强制全图全速，域关闭后 `Valid=false`；逐图自动战斗桥接不使用该旧 API。
- LOS 的逐图线段由调用方的权威几何提供，公共层调用原版逐段检查；掩体在目标图坐标计算。显示矩阵不能用作 Delta-V 命中真相。

## 验证与待完成

### RE 接入新增 API 契约

- 绘制：旧 `BeginFrame()` 保持不清颜色，`BeginFrame(true, color)` 在 1.6 追加颜色/深度清理；1.7 由原生帧管理目标清理。`MapDrawBackend(foreground, name, preserveRenderLayer:true)` 保留辅助 pass 的原生 layer，不将 WaterDepth 编码为主地图深度组。普通地表命令仍用默认分组，捕获命令连同属性范围只在当前帧消费。
- 调度：原五参数 `Set` 保留；六参数重载的 `compensateMovement` 默认不隐式打开。RE 指定 true，移动补偿为 `100/p`，全速例外和 0% 返回 1。0% 的 fullSpeed 谓词变化后须在安全边界调用 `RefreshRegistration`；替换谓词或比例会自动更新注册。位置 setter/直接定位只置脏，`GameComponentTick` 处理变化对象；无 tick 的普通 Thing 不进入暂停登记集合。`Release(map, owner, restoreTicks:false)` 用于立即整图休眠的交接。
- 区域：七参数 `Capture` 的 `includeIntersectingFootprints` 允许多格实体与掩码相交即入选；旧签名保留锚格语义。`MapPrefabDocument.ToXml/FromXml` 支持嵌入消费方存档；实体解析在独立安全的 Scribe 窗口执行。`PrefabPlacement.ProtectCell` 同时保护 terrain/foundation/roof 与建筑 footprint；默认 `SkipProtectedThings=true` 返回跳过列表，false 在写入前报告 footprint 冲突。`PreserveFactions=true` 保留实体派系并解析外部引用，克隆仍分配新实体/Verb 身份。读取与放置失败通过 `Errors` 报告，不得据此丢弃原记录。
- 自动战斗：启动安全点调用 `MapCombatModule.Install()`；`Combat.Enable(map, policy)` 也确保安装完成。`MapCombatPolicy.Owner` 归属消费方，Offset 表示 `targetLocal + offset = sourceLocal`；Available、CellOwner、Neighbors、HasNeighbors 和可选 CanApproach/SuppressTargetSearch/IgnoreProjectile 由消费方提供。两端须登记同一 policy 且有效。框架不推断世界地块或使用显示矩阵作为命中坐标。
- 关闭战斗：`Combat.Disable(map)` 移除逐图登记并使相关目标/弹丸记录失效；`policy.Enabled=false` 对该策略所有地图做同样清理。临时不可用前由消费方调用 `Invalidate(map)`，几何变换改变后也应失效旧目标。关闭图不调用邻居枚举、格归属和弹丸迁移，不获得 tick 提速；没有战斗周期任务。地图删除调用 Forget。弱引用目标/弹丸表属于当前 MapRuntime，换档不继承。
- 战斗安装独立于公共模块。只有 Delta-V 时不安装 REF 战斗补丁；与启用 REF 战斗的 RE 同装时，关闭图仍承担公共 Harmony 方法分派和常数级逐图判断，不能将其描述为绝对零 CPU 指令。CE 保持软反射，缺失不绑定，签名漂移 Warning；原版与 CE 弹丸在当前真实图完成关闭后的剩余原生生命周期。
- 生成：消费方先补齐引用数据，再 `Acquire(owner, completeSynchronously)`，创建图后 `Bind(owner, map)`；完成函数须在同一次调用中结束当前任务并释放，不可等待下一帧或递归 GenerateMap。只有清理完 MapGenerator 静态状态才 `Release(owner)`；清理失败不得释放后继续下一任务。原生 GenerateMap 先 `Drain()` 当前增量任务再登记同步占用；Finalizer 释放。MapPreview 在 GeneratePreview 入口、暂停之前登记，后台线程等待当前占用结束；同线程嵌套立即拒绝。

以上新增能力完成代码接线，双版本实机结果仍按下面的验证边界区分，不复用迁出前的测试结论。

构建和测试入口见 [README](../README.md)。独立 Mod 的 1.6/1.7 加载、地图分层与切图、非矩形区域导出/重建/存读档、整图归档往返、生成中保存和失败释放均需按新档验证。用户已确认迁出前 1.7 护盾与导弹架上层修正有效；这不替代独立打包后的实机验收。

尚待迁入而非“只待验收”的工作：任意既有区域的清空/替换事务、公共资源池与 Gravship 搬运、完整默认多图绘制的逐图 shader 状态隔离。当前 DLL不代表迁移备忘录所有能力已经完成。
