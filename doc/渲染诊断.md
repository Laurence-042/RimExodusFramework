# 原版邻图提交诊断（1.7）

`MapRuntime.Current.Rendering.Diagnostics.StartCapture()` 在主线程显式开始采集，返回文件路径，失败返回 null。`Active` 表示采集尚未结束，`LastPath` 保留最近输出位置，`StopCapture()` 提前停止。1.6 返回不支持（null），不安装额外诊断补丁。默认仅观察，不改绘制；下面的单来源对照须另行显式选择，只临时筛选提交，不改模拟或存档。

## 单来源绘制对照

采集期间，`Sources` 提供当前绘制计划中的来源地图；`TrySetIsolatedSource(map)` 选择其中一个来源，`TrySetIsolatedSource(null)` 恢复全部来源，无效选择返回 false。`IsolatedSource` 表示所选来源。选择在下一帧边界生效，绑定 Map 身份而不是“当前图/邻图”角色，因此切换聚焦不会自动换来源。

所有地图原有 Update/Draw 回调照常运行，视区、变换、裁切和参数冻结沿原路径执行；仅在 REF 的 Enqueue 出口阻止其他**已知来源**的提交。选定来源的队列、矩阵、参数和深度状态不改。来源不明的 `unscoped` 提交保留，避免误删整屏效果；绕过该入口的持久提交和直接 GPU 绘制不在过滤范围。因此这是对已知来源贡献的 A/B，不是完整 GPU 场景隔离证明。

不采集时不能启用；停止、超时、换档、退出地图、切换渲染路径或诊断失败均恢复全部提交并释放来源引用。选定地图不再出现在绘制计划时，也恢复全部来源。选择不序列化。RE 高级诊断页在采集期间提供选择菜单，开始时默认“正常显示全部地图”。

输出为 `GenFilePaths.SaveDataFolderPath/REF-RenderDiagnostics/render-<UTC>.log.gz`（gzip 压缩，解压后为文本）。每秒采一帧，开始及真实聚焦图变化后连续采三帧；60 秒、120 样本帧、约 32 MiB 压缩内容或 512 MiB 原文上限停止。每个来源每帧独立保留最多约四百万字符明细，最多 16 个来源（作用域外提交单独计为一个来源）；前一地图不能占用后一地图额度。超额仅累加分组数量，`SOURCE_BUDGET`/`SOURCE_LIMIT` 明确标注各图省略情况。`Rendering.Clear()` 负责换档、退出显示和切路径时关闭文件、释放采集引用。数据读取/写盘失败只停止诊断并 Warning，不抛入渲染链。

记录类别：

- `FRAME/CAMERA/PLAN/FOOTPRINT`：帧号、时间、真实聚焦地图 ID、BeginFrame 时点相机矩阵、各图局部视区/显示矩阵/覆盖层边界。v3 的 FRAME 另有 `isolatedSource`（-1 为全部），切换时输出 `ISOLATION` 事件并连续采三帧。
- `MESH`：进程内对象身份、版本、子网格、名称、CPU 顶点数与 culling bounds。包围盒可能含 padding，不是精确地形外轮廓。
- `DRAW`：REF 本次 Enqueue Prefix 中的顺序、源图 ID、focus/neighbor/unscoped、shader、材质、裁切前后网格/矩阵、输出 pass/layer、输入/输出队列、实例化对象 ID、参数组 ID。v3 末尾附 `submitted/clipped/isolated`，分别表示本补丁放行、裁切剔除、来源对照隐藏；后者仍记录正常投影后的命令，不能误算成裁切故障。`unscoped` 不推断地图归属。不要把这个顺序当成 Waylith 排序后的 GPU 执行顺序。
- `PROPERTIES`：shader 声明全局值（G/GT）、材质值（M）和本次提交覆盖值（P），带属性 ID；全局项另附注册名称。authored 标记只表示 shader 有自带默认值，G 仍是观察到的全局值，不表示它必定生效。纹理记录对象身份，不读像素；数组等其他引用值也只记录身份。不持有跨帧 arena 范围。
- `COUNTS/GROUP`：完整观察计数与明细省略数，按源图/shader/队列/pass/裁切结果分组。

观察点在 REF 自己的裁切/冻结处理前后，不包含后续 Harmony 补丁的修改，也不捕获直接绕过 Enqueue 的 GPU 提交。采样开始于 Game.UpdatePlay 中的 BeginFrame，之前提交不在该帧样本内。日志用于比较同一地图邻图显示与直接聚焦的差异，不能证明最终深度竞争、透明排序、纹理内容或抗锯齿结果；若提交数据一致仍有差异，需要进一步 GPU 侧证据。采样会短暂增加 CPU/IO 开销。

诊断内容与消费方/第三方 Mod 无关；具体复现条件和责任判断留在消费方调查文档。针对 IsoRim 的使用步骤见同级 RE 的 `doc/IsoRim邻图渲染调查.md`。
