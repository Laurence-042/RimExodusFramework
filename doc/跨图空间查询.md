# 跨图空间查询与 Mod 接入

## 坐标与格子归属

每张真实 Map 的局部坐标、Thing.Map、Thing.Position 和网格登记保持不变。调用方先明确参考 Map，再把源图坐标映射到该参考系。投影成功只表示存在坐标关系，不代表该点属于参考图，也不表示可通行、可见或已加载。

`MapTransform` 用于连续显示空间，可含任意旋转。`MapCellSpace` 用于离散格查询，当前只接受水平整数平移：`sourceLocal + OriginInReference = referenceCell`。不把显示矩阵取整后冒充格子映射；任意角旋转、缩放和跨空间层关系需要另行定义采样语义。

矩形只是地图存储范围。裁切地图必须提供有效区域谓词，void 不自动拥有格子。区域重叠时按 provider 给出的顺序取首个有效拥有者，消费方须明确边界重合规则，不能依赖字典偶然顺序。

## 公共接口

| 接口 | 契约 |
| --- | --- |
| `MapRuntime.Spatial.SetProvider(owner, factory)` | 按消费方登记工厂；传 null 注销。不安装战斗补丁、不添加 tick、不生成或唤醒地图 |
| `TryCapture(owner, reference, out space)` | 获取本次主线程计算的参考系；无 provider、不可用图返回 false。配置错误和 provider 异常交由调用者处理 |
| `MapCellPlacement(map, origin, ownsCell)` | 真实地图、原点在参考系中的位置、有效区域判定；原点 y 必须为 0 |
| `MapCellSpace.TryProject(source, local, out referenceCell)` | 已登记地图的精确整数平移；不检查该点归属 |
| `TryResolve(referenceCell, out MapCellAddress)` | 返回真实 Map 与其局部格；未解析的格没有默认地图 |
| `CaptureGrid(bounds, maxCells)` | 有界密集地址表，适配直接索引数组的算法；默认上限 262,144 格，超限抛异常，不静默缩小范围 |
| `MapCellGrid.ToGrid / ReferenceCell / TryResolve` | 参考系与零基数组坐标转换、结果回写地址；数组按 `z * Width + x` 排列 |

查询空间和地址表只用于当前同步计算。它们冻结平移和地址，不是世界状态快照：建筑、门和屋顶在该次计算中从真实图读取。地图删除、休眠、变更连接或变换后重新捕获；不可序列化，不跨帧缓存。provider 归当前 Game 的 MapRuntime 所有，无需进程静态地图表。

```csharp
runtime.Spatial.SetProvider(owner, reference => BuildSpaceFromConsumerTopology(reference));
if (runtime.Spatial.TryCapture(owner, referenceMap, out var space)
    && space.TryResolve(pointInReference, out var address))
{
    var building = address.Map.edificeGrid.InnerArray[
        address.Map.cellIndices.CellToIndex(address.Cell)];
}
```

`BuildSpaceFromConsumerTopology` 是示意的消费方函数。REF 不知道世界 tile、飞船、谁拥有接缝格，也不会从“正在画哪张地图”推导模拟连接。

## 第三方算法接入步骤

1. 查清输入和输出：观察者来源、是否直接索引 Map 数组、清除/发布时点、额外望远镜或载具分支。
2. 消费方提供真实连接和拥有者，排除未加载、休眠、生成中或不适用地图。未解析格必须明确处理；视野适配采用不透明，不能当成空地。
3. 优先接入公共查询入口。直接索引数组的算法可使用有界联合数据，并保留数组格到真实地址的映射。只读取真实 Thing，不移动其游戏身份，不切真实 CurrentMap，不重复运行 Map tick/update。
4. 结果写回真实图的权威状态。只移动绘制网格不能让可见性、点击、索敌自动一致。
5. 先完成各图自身清空/计算，再合并跨图贡献，最后各图发布一次。下一轮从零构造贡献，观察者离开后不可永久残留。覆盖型模式还需删除该来源先前的跨图贡献。
6. 类型/签名漂移须整体回滚安装；运行时异常丢弃临时贡献并恢复本图算法，明确告警。兼容初始化不得中断启动。

这是共同接入方法，不是未知 Mod 自动兼容承诺。SS 的 shadow casting、望远镜射线、其他 Mod 的 GPU 视野或私有格网需要各自接入点。REF 提供坐标和地址契约，Mod 的视距、透明墙、光照和观察者规则仍由其自身实现。

## SS 与地图背景

RE 的 SS 适配位于其 `Source/Compat/SeamlessSurveillance*.cs`，由 RE 提供表面几何和生命周期政策。两种模拟底层均可使用；细节见 RE `doc/SurveillanceShift跨图视野.md`。

独立的 REF `SurveillanceMapClippersCompat` 修正 SS 无条件设置 `Map.DrawMapClippers = true` 的影响：只在 SS 存在、已安装补丁签名可验证时，按实际 Harmony owner 排在其后，恢复 `generatorDef.disableMapClippers == true` 的明确禁用语义。该判据适用于任意来源的地图，不判断创建它的 Mod、REF 登记 owner、MapParent 类型或太空/地面类别；任何 modder 使用这个原版生成器配置都会得到相同行为。配置不为 true（包括 generatorDef 缺失）时，本适配不改 getter 结果。没有 SS 时不安装此钩子。

## 验证边界

REF 空间/背景契约回归涵盖负坐标、投影与归属分离、void 内的邻图拥有者、逐格地址往返、预算限制、provider 注销和裁片配置。RE 的 `just test-ss` 将统一参考目录的 SS ShadowCaster/ScopeView 源码原样链接到离线测试，使用真实 1.7 Map 网格和生产适配代码；SS 宿主组件和外部联动服务使用夹具，不能代替实际 SS DLL 初始化、渲染或 GPU 验收。
